# Глава 16: Форматы вывода

## JSON

- Атомарная запись через временный файл + rename
- `json.MarshalIndent` с отступами для читаемости

### JSON Schema

Публичный формат отчёта имеет версию `1.1.0`. Его каноническое машиночитаемое описание использует JSON Schema Draft 2020-12:

- [JSON Schema отчёта 1.1.0](../schema/report-1.1.0.schema.json)
- [Санитизированный пример отчёта](../../testdata/report_1.1.0.json)

Схема описывает обязательные поля, необязательные поля с `omitempty`, вложенные данные коллекторов и сводку. `Result.data` содержит один из документированных типизированных объектов либо `null`; результаты BCC обычно используют `null`, поскольку измерения находятся в `histograms`, `events` или `stacks`. Поля `metadata.focus_areas`, `metadata.capabilities` и `summary.anomalies` также могут быть `null`, если соответствующие Go-срезы равны nil.

Обычные тесты без root компилируют схему и проверяют как captured fixture, так и результат `WriteJSON`. Сам сбор не выполняет runtime-валидацию схемы: она остаётся необязательной для потребителей и не влияет на формирование частичных отчётов.

## Flame Graph (SVG)

Визуализация CPU-профиля: ширина = доля CPU-времени, чтение снизу вверх (вызывающий → вызываемый).
